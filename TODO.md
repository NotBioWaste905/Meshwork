# Meshwork — бэклог

Цель MVP (из [MISSION.md](MISSION.md)): рабочий цикл
**граф → канбан/таблица → лог изменений → верификация**.
Порядок фаз — порядок работы; внутри фазы — примерно по приоритету.

## Сделано

- [x] Python/FastAPI бэкенд (in-memory), кастомные ноды задач, связь фронт ↔ бэк
- [x] Соединение/разъединение нод, редактирование задач, авто-лейаут (dagre)
- [x] Каркас Rust-бэкенда (axum), `create_graph`, `add_task`, `get_all_tasks`
- [x] Neo4j → FalkorDB (compose, драйвер)
- [x] Фаза 0 (см. ниже)

## Фаза 0 — снова работает end-to-end

Фронт и Rust-бэкенд говорят на одном контракте; проверено в браузере через `docker compose`.

- [x] Влить ветку `falkordb` в `main`
- [x] CORS в Rust, origins из `CORS_ALLOW_ORIGINS`
- [x] Единый контракт `Task`: `id` от сервера, списки опциональны, `graph_id` из пути, `Status` — `SCREAMING_SNAKE_CASE` строки
- [x] Реализованы `get_task`, `edit_task` (частичный апдейт), `delete_task`, `connect_nodes`, `disconnect_nodes`
- [x] 404 на несуществующий граф/задачу, 400 на пустое имя и self-dependency
- [x] Фронт: graph id в URL (`/graph/[id]`), `/graph` открывает последний граф или создаёт новый
- [x] Фронт: `VITE_API_URL`, ошибки API показываются в тулбаре
- [x] `tags` сохраняются
- [x] Интеграционные тесты хендлеров против FalkorDB (`cargo test -- --ignored`)

- [x] Интеграционные тесты в CI (FalkorDB в service-контейнере)

## Дыры API для нового UI

Новый UI ([docs/design/](docs/design/README.md)) реализован на фронте. Где бэкенд ничего не отдаёт,
экран показывает заглушки из `meshwork/frontend/webapp/src/lib/mock.ts` (в интерфейсе помечены бейджем `mock`).
Бэкенд не менялся.

- [ ] Список графов: нет `GET /v0/graphs`. Главная показывает только графы, открытые в этом браузере (`localStorage`), плюс mock-примеры
- [ ] Метаданные графа: у графа нет имени, цели, времени обновления; имя берётся из терминальной задачи
- [ ] Шаблоны графов (Software release / Hiring pipeline / Incident response) на экране «New graph» — заглушки
- [ ] Авторизация и пользователи: `/login` ничего не отправляет, «Sign out» просто ведёт на `/login`; профиль, роль, дата регистрации, список участников — mock; `Task.users` — свободные строки, «мои задачи» ищутся по имени
- [ ] Аватары участников графа в шапке — mock (нужен список членов графа)
- [ ] Reviewer: нет поля ревьюера; «To review» в профиле заблокирован; «Approve» / «Send back» на странице задачи просто меняют статус и не проверяют, кто нажал
- [ ] Автор задачи и «Created» — нет `created_by` / `created_at`
- [ ] Лог активности задачи и «Recent activity» в профиле — mock (см. «Лог изменений» в фазе 2); колонка «Updated» в таблице и подписи «Updated … ago» на карточках графов не выводятся, нет `updated_at`
- [ ] Комментарии: поле на странице задачи хранит комментарии только в памяти
- [ ] Человекочитаемые номера задач (`T-5`): фронт показывает `T-` + первые 4 символа UUID; нужен сквозной счётчик на граф
- [ ] Тип `CHORE`: на фронте это тег `chore` (пунктирная нода, бейдж CHORE); каденса нет
- [ ] Рёбра `PART_OF` и `AFFECTS` в легенде графа приглушены: в модели их ещё нет
- [ ] «Critical path» на графе — клиентский расчёт самой длинной цепочки `DEPENDS_ON`; серверного эндпоинта нет
- [ ] Настройки: «Notify me when» хранится в `localStorage`, уведомлений нет; «Members and roles» и «API tokens» не реализованы; смена имени/email/фото ничего не сохраняет
- [ ] Группировка на канбане только по статусу; перетаскивание карточек между колонками не сделано
